# Промпт: перепроверка и завершение глубокой доработки Moira

## Роль
Ты — объединённая команда: senior Python/aiogram-разработчик, эксперты по Rider–Waite–Smith, prompt engineering, редактор RU/EN, UX-writer, дизайнер Telegram-графики, специалист Pillow, QA по контенту и визуалу.

## Исходные документы (прочитай полностью, в таком порядке)
1. `Глубокая доработка внутреннего содержания Moira.docx` — **оригинальный промт этой работы** (20 этапов). Это источник требований, сверяйся с ним постоянно.
2. `docs/CONTENT_IMPROVEMENT_REPORT.md` — отчёт агента, который работал до тебя (дальше — «предыдущий агент»).
3. `docs/CONTENT_AUDIT.md`, `docs/CONTENT_SPEC.md`, `docs/READING_QUALITY_RUBRIC.md` — документы, созданные в предыдущем проходе.
4. `docs/STABILIZATION_REPORT.md` — техническая стабилизация; **не ухудшай и не откатывай её исправления**.

## Главная задача в двух фразах
1. **Перепроверь фактами** (кодом, тестами, реальными вызовами — не доверяя отчёту) каждое заявление предыдущего агента по этапам 1–20 оригинала.
2. **Исправь найденные ошибки и доделай всё, что не доделано**, включая обязательную визуальную галерею, визуальный ревью-док и 48 контентных сценариев.

## Часть A. Перепроверка (сначала — факты, потом — правки)

Проверь кодом и запусками, НЕ по отчёту:

**A1. Колода и контент карт**
- `build_deck()` возвращает ровно 78 карт, id уникальны.
- У каждой карты: RU и EN, upright и reversed, essence, keywords, light/shadow/advice (по этапу 5 спеки), у всех 22 Старших — symbols (2–4) и reflection_question.
- upright ≠ reversed содержательно, не только другой строкой.
- 56 Младших — уникальные комбинации масть×ранг, нет шаблонных повторов текста (этап 2 спеки: отсутствие точного дублирования больших блоков).
- Проверь согласованность названий карт между `data_major.py`, `i18n/locales/`, `assets/cards/` и индексами в БД.

**A2. Расклады** (Этап 3 оригинала)
- Три расклада (Ситуация/Любовь/Выбор) — позиции содержательные и разные, нет дублей, каждая позиция объясняется пользователю.
- Проверь, что LLM-промпт передаёт позицию карты и что `POSITION_MEANINGS` заполнены RU/EN для каждой позиции.
- Проверь, что синтез реально связывает карты (последовательность, масти, стихии, паттерны), а не повторяет три значения.

**A3. Падение LLM → fallback** (Этап 5)
- `bot/tarot/fallback.py` — вызови `compose_fallback_reading()` на всех трёх раскладах, RU и EN, mixed/reversed/все-старшие кейсах. Проверь: паттерны, позиции, рефлексивный вопрос, отсутствие ложной персонализации.

**A4. «Мой Аркан»** (Этап 7)
- `quiz.py`: полный перебор 4^6 = 4096 комбинаций → все 22 Аркана достижимы; распределение без непропорционального доминирования; tie-break детерминирован; **в коде нет `% 22`** (проверь регэкспом весь файл, включая скрытые места, а не только глазами).
- У всех 22 Арканов есть RU/EN: название, архетип, сильная сторона, теневая сторона, текущая задача, девиз, вопрос. Объём 700–1100 символов.

**A5. Карта дня, лунный контекст, недельное зеркало** (Этап 6)
- Карта дня: 4 элемента (тема / внимание / действие / вопрос), 500–750 символов, не вырождается в обычный расклад.
- Лунный контекст: расчёт корректен, хэш/рандом не выдаётся за астрономию.
- Недельное зеркало: использует только реальную историю.

**A6. Тексты RU/EN** (Этап 8)
- Паритет ключей i18n: `ru.json` ↔ `en.json` (прогони скриптом разницы ключей — должно быть 0 с обеих сторон).
- RU: естественный современный язык, женский род Moira, нет канцелярита и кальк с английского.
- EN: neutral international English, не дословный перевод.
- Сверь фактический текст кнопок/сообщений с CONTENT_SPEC.md; укажи расхождения.

**A7. Тесты**
- Запусти `./.venv/Scripts/python.exe -m pytest tests/ -q`. Зафиксируй число passed.
- Проверь, что каждый тест реально проверяет утверждаемое (посмотри сами тесты, а не только их «зелёность»).

**B2. Дизайн-токены** (Этап 12.1)

- Запрет: магические числа по функциям Pillow; `ImageFont.load_default()` — только аварийный fallback, основной шрифт — project-local с кириллицей+латиницей (проверь лицензию и наличие файла шрифта в проекте).

**B3. Контентная тестовая выборка** (Этап 14)

- Для каждого: `must_reference_positions`, `must_distinguish_reversal`, `must_include_synthesis`, `must_not_assert_other_person_thoughts`, `must_include_reflection_question`, `maximum_length`.

**B4. Верификация LLM-схемы** (Этап 4/7.2 спеки)
- Проверь Pydantic-схему чтения: все поля (headline, opening, card_interpretations[position/card_name/orientation/core_message/symbolic_detail/context_connection], synthesis, practical_focus, reflection_question, voice_summary, share_summary).
- Длины по ориентирам спеки (headline ≤90, opening 120–250, карта 300–550, synthesis 500–900, focus 180–350, question ≤220, voice 500–800, share 180–300 символов).
- voice_summary — отдельный устный текст; share_summary не содержит приватного вопроса пользователя.

**B5. Тон Моира** (Этап 4.1)
- Проверь промпты на: женский род, баланс тона 20/60/20, запрет «я чувствую твою энергию», «такова судьба», повторение имени пользователя в каждом абзаце, одинаковые начала ответов.

## Часть C. Исправление ошибок
Любую найденную ошибку (в перепроверке или в новых артефактах) исправляй сразу, но:
- не переписывай проект и не меняй архитектуру;
- не меняй aiogram, БД без доказанной необходимости, тарифы, payment/referral/deployment;
- не откатывай стабилизационные исправления;
- после каждого блока правок запускай связанные тесты + весь smoke suite;
- не коммить и не пуши в remote (репозиторий не инициализирован — просто оставь изменения на диске);
- RU и EN — единственные языки, не добавляй другие.

## Порядок работы и отчёт
1. Часть A (перепроверка) → напиши конец отчёта в `docs/REVERIFICATION_REPORT.md`: для каждого пункта — ✅/❌/⚠️ + факт (строка кода, вывод команды, число тестов).
2. Часть B (доделки) → создание артефактов + `docs/VISUAL_REVIEW.md`, `tests/content_cases.json`, `tests/test_content_cases.py`.
3. Часть C (исправления) — с тестами после каждого блока.
4. Финальный вывод в `docs/REVERIFICATION_REPORT.md`: расхождения между отчётом предыдущего агента и фактом; список созданных файлов; результаты всех тестов; что требует ручной проверки человека (особенно читаемость изображений на реальном телефоне).

**Критерий завершения:** не говори, что «визуал готов», пока в `artifacts/visual_review/` нет файлов и они не открыты/проверены. Не говори, что «48 сценариев проходят», пока не запущен `tests/test_content_cases.py`.
